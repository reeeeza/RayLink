V2S Mac redemption correction — November 3, 2026

COMPLETED
- Fixed the macOS 27 redemption callback: it previously discarded the VerificationResult<Transaction> returned by Apple's current API and only refreshed currentEntitlements. It now sends the returned transaction directly through the existing Apple-signature + live V2S-server verification + profile delivery + transaction.finish path. A delayed entitlement snapshot can no longer substitute for the returned redemption result.
- Launch, foreground refresh and Restore now consider active verified unfinished transactions as well as current entitlements. Candidates are deduplicated, latest expiry first; a failed candidate does not hide another valid subscription. Failed delivery is not finished and can be retried without redeeming again.
- Transaction updates use the serialized reconciliation path instead of racing concurrent snapshot checks. Rejected redemption revalidates an independently existing subscription. No local Premium flag, fabricated receipt, account allowlist or unconditional code acceptance was added.
- Development/test installations identify their purchase environment. Redeem explains that a regular Apple Account cannot convert this build into a production Store build and offers the official Mac App Store page. Production builds retain Apple's native supported redemption sheet. Network, storefront and cancellation failures have distinct messages; Apple continues to validate individual codes and eligibility.
- Existing monthly/yearly product IDs, pricing, server verification, privacy consent, expiry enforcement, free tier and settings are preserved. No code, receipt, transaction or credential is stored in this report.
